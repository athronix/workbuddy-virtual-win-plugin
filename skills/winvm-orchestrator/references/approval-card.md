# 审批卡片模板 v1（L2 / L3 · 唯一正文）

> **唯一性红线**：本文件是审批卡片的**唯一正文**。其它 Skill（如 `winvm-orchestrator`、各能力 Skill）**只允许引用本文件**（写一行 Markdown 相对链接：[`../winvm-orchestrator/approval-card.md`](../winvm-orchestrator/approval-card.md)），**不得复制模板正文**。任何副本都会引入漂移，一律视为违规。

> **展示先于执行**：本模板是「展示先于执行」闸门的载具。**未经展示与用户确认，任何 L2/L3 操作不得执行**。本全文**不含**任何「可跳过 / 可自动批准 / 可默认放行」的表述；任何此类表述都是对审批闸的破坏。

## 1. L2 版（破坏性可回滚类）

```text
🔐 需要你确认（L2 破坏性操作）

[操作] storage.file.delete（删除文件）
[目标] C:\Users\vmuser\Documents\old（3 个文件）
[通道] A2A 委派 · task_01J8QX  ←（MCP 直调时写：MCP 直调）
[风险] L2 — 破坏性：会改变系统状态
[影响清单] 3 项
  1. C:\Users\vmuser\Documents\old\a.log（12.4 MB）
  2. C:\Users\vmuser\Documents\old\b.log（8.1 MB）
  3. C:\Users\vmuser\Documents\old\c.log（2.3 MB）
[可逆性] 可逆 —— 默认进回收站，可从回收站还原
[预览] 将删除 3 个文件，预计释放 22.8 MB；不触碰该目录以外的路径
[审批ID] apr_8f3c

请回复「批准」以继续，或回复「拒绝」以终止。
未经确认不会执行任何变更。

（MCP 通道续跑指令）以同一参数并附 __approvalId="apr_8f3c" 重新调用本工具
（A2A 通道续跑指令）a2a.approval.reply { taskId: "task_01J8QX", approvalId: "apr_8f3c", approved: true }
```

**7 个槽位**：操作 / 目标 / 通道 / 风险 / 影响清单 / 可逆性 / dry-run 预览，外加 **[审批ID] + 续跑方式**。缺数据时按 §5 降级文案填充，**不得留空**。

## 2. L3 版（关键高危、不可逆类）

```text
⛔ 高危操作，需要二次确认（L3）

[操作] system.power.control（关机 / 重启 / 休眠）
[目标] 虚拟机 172.16.100.2
[通道] MCP 直调
[风险] L3 — 关键高危
[影响清单] 1 项
  1. 目标机 172.16.100.2 将失去响应，当前所有前台会话与未保存内容受影响
[可逆性] ⚠️ 不可逆 —— 无法自动回滚
[预览·dry-run] 已展示将执行的动作与影响范围；本次预览未执行任何变更
[审批ID] apr_9d21

⚠️ 二次确认（必填）：
请回复完整短句「确认执行关机」以继续。仅回复「好的 / 可以 / 继续」不会被接受。
在完成上述二次确认前，本操作不会被执行。

（MCP 通道续跑指令）以同一参数并附 __approvalId="apr_9d21" 重新调用本工具
```

**L3 额外要求**：必须出现「不可逆 / 无法自动回滚」判定，并给出**二次确认短句**要求（L3 一律要求完整短句，**仅回复「好的 / 可以 / 继续」不被接受**）。

## 3. L3 预览的获取方式（原「阻断态」已移除）

> **变更说明（CL-017 D11）**：策略层已支持 **`dryRun: true` 免审批放行** —— 凡是支持 `dryRun` 的 L2/L3 能力，
> 带 `dryRun:true` 调用**直接返回变更计划**（`approval.preview` 会附带 dry-run 计划摘要），**不产生审批卡片**。
> 因此 L3 的 dry-run 预览**总能先行取得**，原先「dry-run 预览未就绪 → 阻断」的**分支不再可达，已删除**。

L3 的正确次序：**先 `dryRun:true` 免审批拿预览 → 展示影响清单 → 二次确认 → 去掉 `dryRun` 执行**。

若某能力**确实既不支持 `dryRun`、又不下发 `preview`**（异常情况）：**不得编造预览**，
按 §5 写 `预览：未提供` 并**明确告知用户无法预览**，由用户显式确认后才继续 —— 但**不得**自行放行。

## 4. 槽位 ↔ 数据来源对照表（宿主照填用）

| 槽位 | MCP 直调来源 | A2A 委派来源 | 无数据时的降级文案 |
|---|---|---|---|
| 操作 | `approval.capabilityId`（+ 工具 `title`） | `approval.capabilityId` | `操作：<未提供>（请勿确认）`——**不得猜测** |
| 目标 | `approval.preview.params` 中的路径/对象字段 | 同左（`preview` 透传后字段一致） | `目标：见影响清单` |
| 通道 | 固定「MCP 直调」 | 固定「A2A 委派 · <taskId>」 | 不适用 |
| 风险 | `approval.risk` | `approval.risk` | 无 => **不出卡片**，明确报错 |
| 影响清单 | `approval.impact[]` | `approval.impact[]`（透传后） | `影响清单：VM 未提供（按参数推断：…）`——须标注为**推断** |
| 可逆性 | 由 `preview.params` + 能力语义判定（如 `permanent`） | 同左 | `可逆性：未知 —— 按不可逆处理` |
| dry-run 预览 | `approval.preview` 关键字段 + 说明（含 dry-run 计划摘要） | 同左（`preview` 透传后） | L2：`预览：未提供`；**L3：先以 `dryRun:true` 免审批取得 preview（见 §3）** |
| 审批 ID + 续跑 | `approval.approvalId` + `resumeHint` | `approval.approvalId` + A2A 续跑指令 | 无 => **不得出卡片**（无从应答） |

## 5. 降级文案固定串（逐字使用，禁止改写）

- 目标缺失 → `目标：见影响清单`
- 影响清单缺失 → `影响清单：VM 未提供（按参数推断：…）`（**必须**标注「按参数推断」）
- 可逆性未知 → `可逆性：未知 —— 按不可逆处理`
- 操作缺失 → `操作：<未提供>（请勿确认）`（**不得猜测**）
- L2 预览缺失 → `预览：未提供`
- L3 预览缺失 → 先以 **`dryRun:true` 免审批**重新调用取得 preview（见 §3），再出确认卡片；**不得编造预览**

---

## 6. 可逆性判定规则（呈现层职责，**不在代码里硬编码**）

| 条件 | 判定文案 |
|---|---|
| 删除族能力（默认） | `可逆 —— 默认进回收站，可从回收站还原` |
| `preview.params.permanent === true` | `不可逆` |
| `risk === 'L3'` | `不可逆 —— 无法自动回滚` |
| 以上均不匹配 / 未知 | `未知 —— 按不可逆处理` |

判定优先级：`risk === 'L3'` 与 `permanent === true` 均判「不可逆」；其余删除族默认「可逆」；不确定一律按不可逆处理。**判定结果必须与参数一致**（参数说永久删除，就不得写「可逆」）。

---

## 7. 不弹卡清单（以下情形**不产生**审批卡片、**不产生**二次确认）

- **L0 / L1 操作**：直接执行，**不产生**审批卡片与二次确认。L0=只读；L1=可回滚写。
- **未注册能力**（如 `storage.volume.destructive`，V1 未注册）：**不产生卡片**，改为输出固定串：
  `本系统不提供该能力，需人工在 VM 内执行`
- **缺少 `approvalId`**：无从应答，**不得出卡片**（见 §4 末行）。

> 说明：不弹卡 ≠ 放行未注册能力；未注册能力是**拒绝执行**，只是以文字提示替代卡片。

---

## 8. 填充红线（违反即视为审批闸失效）

1. **任一槽位不得留空、不得写 `N/A`**；缺失必须走 §5 固定降级文案。
2. 无数据时必须显式标注「未提供 / 推断」，**不得编造**任何路径、数量或影响。
3. **凭据类字段永不进入卡片**：`password` / `privateKey` / `passphrase` / token / secret 一律**剔除**，不得出现在任何槽位或预览中。
4. 可逆性判定必须与参数一致（见 §6）。
5. 卡片**只展示，不放行**：卡片本身不得携带任何 `approved=true` 结果；放行只能来自用户的显式确认。

---

## 9. 续跑指令（两条通道各一行，仅作对照说明）

- **MCP 直调续跑**：以同一参数并附 `__approvalId="<approvalId>"` 重新调用本工具。
- **A2A 委派续跑**：`a2a.approval.reply { taskId: "<taskId>", approvalId: "<approvalId>", approved: true }`

> ⚠️ **通道隔离红线**：`__approvalId` 是 **MCP 直调**的续跑标记；**A2A 委派通道的输出中绝不能出现 `__approvalId`**。两条通道的续跑指令不可混用。
