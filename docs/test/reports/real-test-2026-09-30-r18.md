## 3. 新发现缺陷登记：`C:/` 字面量路径在鸿蒙宿主物化（与 %LOCALAPPDATA%/ 同类）

**四元组**：

- **现象**：仓库根出现字面量目录 `C:/WinVMBridge/shared-skills/`（7 个技能子目录 + SKILL.md，内容与仓库 `skills/` 一致），git status 报 `?? C:/`。同历史缺陷家族：`%LOCALAPPDATA%/`（未展开 Windows 变量落盘，已收录 .gitignore）。
- **根因**（文件+行号）：`delivery/install-vm.mjs` 是 **VM 侧安装器（仅应在 Windows VM 内运行）**，本轮 VM 不可达时被在**鸿蒙宿主**上直接执行（apply 补偿跑）；其步骤 4 `deploySkillsStep`（install-vm.mjs:416-425，调用点 :702）取共享根 `DEFAULT_SHARED_SKILLS_ROOT = 'C:/WinVMBridge/shared-skills'`（deploy-shared-skills.mjs:25），`publishSharedSkills` 无条件 `await mkdir(sharedRoot, {recursive:true})`（deploy-shared-skills.mjs:240）+ `cp(...)`（:241）。**POSIX 平台盘符路径不是绝对路径**——`C:/…` 按相对路径解析于 cwd（仓库根）→ 在宿主仓库里物化出 `./C:/WinVMBridge/shared-skills`。全链 grep `process.platform` 零命中：install-vm.mjs 与 deploy-shared-skills.mjs **均无平台守卫/路径形态守卫**。
- **证据**（时间戳链条吻合，纳秒级）：vm-service.runtime.json（步骤 3 writeJson）15:25:59.**378** → `C:` 目录建立 15:25:59.**382**（晚 4ms）→ 各 SKILL.md cp 15:25:59.390–.450 → start-hidden.ps1/task.xml（步骤 5 buildTaskXml）15:25:59.**518** → apply 日志落盘 15:26:00.19；而 `T01-vm-deploy-attempt.txt`（deploy-vm 远程 ssh 失败早退）15:25:**52**——时间序证明 C:/ 产生于 ssh 失败**之后**的 install-vm 本地跑，非 deploy-vm 的 tar/scp 步骤（该步在远程 mkdir 失败后即 return，未打包）。旁证：`T01-vm-deploy-apply.log` 内容是 install-vm 的**本地输出**——"仓库根目录 : /storage/Users/…"（宿主路径）与 "VM 内 Node.js — 检测到 v24.13.0"（实为宿主 bundle node），证明该脚本跑在宿主而非 VM。
- **修复建议**（本轮只登记不改码）：
  1. `install-vm.mjs` main 入口加平台硬守卫：`process.platform !== 'win32' && !args.dryRun` → 拒绝执行并提示"本脚本仅应在 VM 内运行，宿主请用 deploy-vm.mjs"（或显式 `--allow-off-vm` 逃生门）。
  2. `deploy-shared-skills.publishSharedSkills` / `deploySkillsStep` 加路径形态守卫：非 win32 平台下 `sharedRoot` 匹配 `/^[A-Za-z]:[\\/]/`（或未展开 `%ENV%`）→ 跳过发布并 WARN，与 %LOCALAPPDATA% 教训同型收口。
  3. 部署文档/install-vm 头部补"VM 不可达时禁止在宿主裸跑 install-vm"处置口径（deploy-vm 失败提示语已是正确出口）。
  4. 已做：`.gitignore` 追加 `C:/`（与 `%LOCALAPPDATA%/` 相邻同模式）；**垃圾目录本轮不删除**，留作缺陷证据（rm shim 亦坏，不强删）。
