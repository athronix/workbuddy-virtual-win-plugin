## 4. 代码审查（安全闸重点）

### 4.1 `packages/vm-service/src/server.ts` —— 三点全部确认 ✅

1. **PendingApproval 有 `hostApproved` 字段且注册时恒 false**（L54-67、L365-366）：字段带安全注释「杜绝不记名令牌漏洞」；`/mcp` handler 在 `verdict.requiresApproval` 分支注册 token 时显式 `hostApproved: false`。
2. **续跑放行判定是严格等值 `hostApproved === true`**（L341-343）：
   ```ts
   const approved = approvalId !== undefined
     && pendingApprovals.get(approvalId)?.hostApproved === true;
   ```
   不是 `pendingApprovals.has(approvalId)`；token 不存在/未批准/字段缺失均不放行。
3. **VmApprovalCoordinator.raise 链路正确**（L107-118 + L525）：`raise` → `task-store.waitApproval(activeTaskId, req)` 挂起任务；`done.then(approved => approved 时才置 p.hostApproved = true)`。`bind(a2a.tasks, pendingApprovals)` 在二者就绪后调用一次（L525）。

### 4.2 `packages/a2a-framework/src/server.ts` —— 安全网确认 ✅

- **taskId 注入**（L295-297）：`runGoalWithLifecycle` 内 `Object.assign(goal, { taskId: id })`，桥接层可把挂起挂到正确任务。
- **input-required 不被覆盖的安全网**（L308-313）：handler 返回后先 `tryGet(id)`，若 `state === 'input-required' || pendingApproval` 存在则**直接 return**，不写 completed/failed 终态 —— 逻辑存在且正确。
- **终态收口**（L301-305）：sink 的 onStatus 拦截 completed/failed，由 lifecycle 统一写入，避免 provider 与框架竞争。
- **continueTask 审批应答**（L255-286）：DataPart 中 `approvalId`+`approved` → `resolveApproval`；未决审批不存在时报 InvalidParams（防重放/过期 token）；`approved=false` → 任务置 `rejected` 终态，**绝不续跑**；`approved=true` → 状态回 working，由挂起的 runner 自行续跑。

### 4.3 旁证（task-store / bridge / contracts）

- `task-store.ts` L151-202：`waitApproval` 置 input-required 并挂 promise；`approvalMessage` 的 DataPart 含 `type:'approval-request'`、approvalId、capabilityId、risk、preview、impact —— 结构化审批事件符合修复目标；`resolveApproval` 严格校验 approvalId 匹配。
