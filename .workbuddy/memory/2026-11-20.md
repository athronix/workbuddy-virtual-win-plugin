## V1.4.36 → V1.4.37：host-only 语义从「加开关」到「分支顺序」

### V1.4.36 只修了一半

`9e0b267` 新增 `--host-only` + `planVmPhase`，让「VM 相位跳过」不再计入失败 —— 解决了**计数**。
但 `printVerification` 里 `if (vm)` 排在 `hostOnly` 之前，生产机上 `vm-conn.json` 恰好存在
⇒ `--apply --host-only` 仍会走进 VM 分支、去连 SSH，最后落 `else` 打出
**`[PASS] VM side checks (observed: skipped (dry-run))`** —— 在 `--apply` 场景下这句自相矛盾。

**教训：加开关 ≠ 开关生效。决策函数写对了，接线顺序错了照样打脸，而且打的是「最该看清的那一行」。**
`0c1bcaa` 把分支前移为 `if (hostOnly) / else if (vm)`，措辞改 `skipped (VM phase did not execute)`，
并加测试钉死分支顺序（`assert iHostOnly < iIfVm`）。

### v2.5.7 门禁踩的两个坑

1. **`--host-only` 子串假绿**：该字样同时出现在调用行、判据行（`HOSTONLY_NEW=... awk`）、
   诊断行（`grep -E`）。只查子串时**删掉调用处的开关仍能命中** ⇒ M60/M61 双 `[MISSED]`。
   改 `re.search(r'delivery/uninstall\.mjs\s+--apply\s+--host-only', body)` 锚定实际调用行后才
   `ALL_CAUGHT 61/61`。**门禁的全绿本身不算证据，突变反证才算。**
2. **awk 正则里的转义**：脚本写的是 `'\[PASS\] HOST'`（带反斜杠），按字面 `'[PASS] HOST'` 匹配
   永远失败 —— 首次跑就误报 `判据丢了 HOST 行`。

### v2.5.8（本轮）：只补排错表，代码零变更

V1.4.37 是**纯母项目侧**修复（分支顺序 + 措辞），skill 侧无需改代码。但排错表缺一条：

### 重大环境发现：hmdfs 的 `~/.ssh/config` **不可用**（本条最有价值）
- `~/.ssh/config` 属主是 **20001006 (file_manager)**，而当前进程 uid 是 **20020171**。
  OpenSSH 强制要求 config 属主 == 当前 euid，跨 uid 直接拒：
  `Bad owner or permissions on /storage/Users/currentUser/.ssh/config`（rc=255）。
- 此错误**会拦截所有 ssh 调用**（连 `-i` 指定别把钥也一起废掉）——因为 ssh 启动时先读默认 config。
- 想改权限位也没用：hmdfs 上 `chmod` 对新建文件会**保留组读写**，写 `600` 实际落成 `660`；
  但 `id_ed25519` 这类**老文件**（600）可以正常 chmod。⇒ 结论：不是权限位问题，是**属主 uid 不匹配**，无解。
- 另外 `rm` shim 坏（`bad interpreter: No such file or directory`）导致 `rm -f config` 静默失败，
  进而 `cat > config` 追加到原 inode、权限仍是 660 —— 两个坑叠加，极易误判成"chmod 没生效"。
  正解用 `node -e 'fs.unlinkSync(...)'`。
- **正确调用方式**：不要建 `~/.ssh/config`。一律显式传：
  `ssh -i ~/.ssh/id_ed25519_gitee -o IdentitiesOnly=yes ...`
  或 `GIT_SSH_COMMAND="ssh -i $HOME/.ssh/id_ed25519_gitee -o IdentitiesOnly=yes" git ...`
  （GIT_SSH_COMMAND 只对 git 生效，对裸 ssh 无效 —— 本轮踩过一次误判。）
