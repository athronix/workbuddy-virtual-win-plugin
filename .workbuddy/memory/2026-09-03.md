## 诊断：第一次重装 /health 不通、两次 node.exe 弹窗、degraded 非锁屏
- 用户按"卸载→重装→再卸载→再装"闭环实测，提三问。逐条追码定位：
- **Q1 为什么第一次 /health 不通、第二次就通**：
  - `setup.mjs` HEALTH 阶段（`setup.mjs:561-577`）只做 **3 次尝试、间隔 3s**（每次 `curl --max-time 15`）。
  - 但 `/health` 只在服务**完全启动后**才响应：`vm-service/src/server.ts:506` 的 `server.listen()` 位于
    `createService()` **末尾**，之前要等 ps-bridge 常驻 PowerShell 握手（`ps-bridge.ts:212` ready 上限 15s）+ provider 加载。
    冷启动（尤其刚 `schtasks /run` 后）整个 boot 可能 >9s，前几次 curl 多为连接拒绝（瞬时返回，并非等满 15s）→ 3 次≈9s 不够。
  - 第一次 `schtasks /run` 是**异步触发**立即返回，node 进程在后台继续启动；HEALTH 放弃后该进程**仍在后台启动并最终监听 18443**。
    第二次 `schtasks /run` 受任务 XML `MultipleInstancesPolicy=IgnoreNew`（`install-vm.mjs:174`）约束→**不再起新实例**，
    只探测到第一次那支已就绪的进程 → /health 第 2 次即通。**本质是"冷启动 + 探针窗口太短"的竞态，第二次搭了第一次的便车。**
  - 另：卸载只 `schtasks /Delete` **任务，不杀运行中的进程** → 旧进程残留占住 18443（这也是为什么"第二次"能立刻通）。
- **Q2 两个 `node.exe` 弹窗能不能关、是否影响 MCP/A2A**：
  - 任务 XML `LogonType=InteractiveToken` + `Hidden=false`（`install-vm.mjs:168-181`）→ 在交互式会话里跑 `node cli.js`
    会**弹一个控制台窗口**。①黑屏/卡住的那个 = **WinVMBridge.Service 服务本身**（node cli.js）。**关掉它=杀服务，/mcp 与 /a2a 全断。**
  - ②带日志打印的那个 = **worker 子进程**（或上次残留的重复服务实例）：确定性 `workbuddy` provider
    （`adapter-agent-workbuddy/src/index.ts`）执行能力时**只调 ps-bridge(PowerShell)，不 spawn node**；
    故该窗口最可能是 **残留的旧服务实例**（卸载没杀进程）或 LLM provider 的 `codebuddy` CLI。
    **关掉它只影响那一个任务/实例，服务通道(MCP/A2A)不受影响**（前提是①还活着）。
  - 建议清理重复：在 VM 内 `taskkill /F /IM node.exe`（仅针对 `cli.js --host 127.0.0.1 --port 18443` 的进程）后，
    确认已 RDP 登录再 `schtasks /run /tn WinVMBridge.Service` 一次。
- **Q3 为什么 `state:degraded`「GUI 不可用」但 VM 没锁屏**：
  - 健康判定在 `vm-capabilities/psmod/gui.ps1:42`：`$interactive = ($sessionId -ge 1) -and ($ws -eq 'WinSta0') -and $explorerAlive`。
    三项任一不满足即 degraded；而 `/health` 返回 `interactive:false` + `windowStation:"W"`（**不是** `WinSta0`）
    → 服务进程**不在交互式桌面会话**（典型 `windowStation:"W"`/非 WinSta0 即非交互）。
  - **根因不是锁屏**：`locked:false`。真正原因是**部署时 `schtasks /run` 经 SSH 触发、当时 VM 上没有活动的 RDP 交互式登录会话**
    → 任务落到**非交互会话（近似 Session 0）**，没有 WinSta0\Default 可视桌面 → GUI 能力被门禁
    （`health.ts:41-43` `guiAllowed` 要求 `state==='healthy' && interactive`；`server.ts` 的 buildHealth 把 `interactive:false` 标 degraded）。
    用户后来 RDP 进 VM 看到的 node.exe 窗口**与探针所检视的服务进程不是同一会话上下文**。
