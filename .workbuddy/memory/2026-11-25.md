### 3.2 `p8-probe-fresh`（12 条全红，exit 127）

但报错文案是「probe-fresh 恒 exit 0」这种误导性描述。

- 覆盖从原 8 条扩到 13 条，新增原版**没覆盖**的两道保守面：全绿门 `deploy_ok≠1`、

### 3.3 顺带发现并修掉一个真实生产缺陷（CRLF）
`sed -n 's/^deploy_ok=//p'` 读 CRLF stamp 会残留 `\r` ⇒ `"1\r" != "1"` ⇒ 恒判
`deploy-not-green` ⇒ **复用永久失效**（每次冷跑 +240s，不报错、不看 reason 发现不了）。
- 修法：`deploy-5-verify.sh` 加 `_probe_field()` 统一 `| tr -d '\r'`
- 这正是 legacy 版原本要防的面，内联时丢了 —— 重写单测把它重新钉住
- **三次突变反证**：`-gt`→`-ge` / 删 `tr -d` / 删 `deploy_ok` 判断，全部被抓
- **★ 修复已落在技能仓，不在母项目**：`deploy/` 是技能仓的工作区挂载（母项目 `git ls-files deploy` = 0）
  ⇒ 修复提交在 `~/Documents/projects/skills/winvm-plugin-deploy`，commit `3fd8b8e`，**升 v2.6.4**
  （README 版本纪律：文案 PATCH）。技能自检 `SELFCHECK=ALL_GREEN checks=37 fails=0`
  ⇒ 若只在母项目改脚本，**下次别人 pull 母项目得到的仍是旧脚本**，这个坑必须记住。

### ★ 3.4 一个操作教训（自己踩的）
改 `deploy-5-verify.sh` 做突变反证时，**同时**有一个全量 `npm run test:unit` 在后台跑。
`p8-probe-fresh` 是**运行时从该脚本抽判定块执行**的（不是读快照）⇒ 突变期间它读到 `-ge` 版
⇒ 全量单测报 `failed=1`，看起来像新回归。实际是**我自己制造的竞争条件**。
**纪律：做文件突变时不得有依赖该文件的测试在跑；突变完先还原再起全量。**
