## §8 irm|iex 引导必挂的真根因：载荷 UTF-8 BOM（16:40 用户回传实证）
- **现象**：用户粘 1c 的「irm 备选」命令 ⇒ `[scriptblock]::Create` 阶段抛
  `意外的属性 CmdletBinding` / `表达式或语句中包含意外的标记 param` / `赋值表达式无效`（行 83/84/85/87/94/95/99/104/106），**脚本一行都没执行**。
- **根因 1（主因）**：`winvm-sshd-oneclick.ps1` 存盘带 **UTF-8 BOM（EF BB BF）**。
  `-File` 执行时 BOM 在解码阶段被当编码标记吞掉；`irm|iex` / `[scriptblock]::Create(<已解码字符串>)`
  里 BOM 留在开头 ⇒ 首行 `#requires -Version 5.1` 不再被认成指令 ⇒ `param` 块脱离「脚本参数区」
  ⇒ `[CmdletBinding()]`/`param`/赋值全判非法。（`od -An -tx1` 取证：efbbbf 仅在 oneclick，其余 20 个 .sh/.ps1 均无 BOM。）
- **根因 2**：`Invoke-RestMethod` 对 text/plain 可能返回 `string[]`，`Create` 按 `$OFS`（空格）**拼成一行**。
- **修复（技能仓 `6d8b81e`，双端已推）**：① 载荷去 BOM；② 删 `#requires`，版本门槛改 param 之后运行期检查；
  ③ 1c irm 备选内联 `$s=[string]::Join([char]10,@($s))` 归一化；④ 门禁新增 `iex-safe`（无 BOM/首行非 #requires/备选有归一化）
  + 变异 M21/M22。**门禁 `ALL_GREEN checks=22 fails=0` / `ALL_CAUGHT 22/22`**。
- 远端验证：Gitee raw 302→raw.giteeusercontent.com、GitHub raw 直连，两端最终 `text/plain; charset=utf-8`、
  **sha256 一致 `dca27901968659b3…`、154814B、首字节 `3c 23 0a`（`<#\n`）无 BOM**。
- **通道现状**：11-17 16:52 三段取证 = ping 0% 丢包 / 裸 TCP 12s**零 banner** / 隧道进程与 `health` 均不在
  ⇒ 经典 **WEDGE**（sshd 预认证段停摆）+ 第二轮卸载已停机。等用户重跑 oneclick 重建（会顺带重启 sshd）。

## §11 复用核查：本项目 GUI 的 Session 0/1 既有解法（回答 agent-desktop 落地问题）
- **正解不是"修 Session 0"，而是让服务进程本身生在 Session 1**：`delivery/install-vm.mjs` `buildTaskXml()`
  生成计划任务 XML（**绝不注册为 Windows 服务**），要点四层：
  1. `<Principal><LogonType>InteractiveToken</LogonType><RunLevel>HighestAvailable</RunLevel>`；
  2. **双触发器** `BootTrigger` + `LogonTrigger`：开机触发落 Session 0（系统/网络/应用类能力可用，GUI 不可用），
     登录触发在交互会话再起一次；
  3. `MultipleInstancesPolicy=StopExisting` ⇒ 登录触发会把 Session 0 实例停掉再起 Session 1 实例；
  4. `ExecutionTimeLimit=PT0S`（不限时）+ `RestartOnFailure PT1M×3`。
- **隐藏窗口必须进程创建层做**（教训 A4）：InteractiveToken 任务**忽略** `<Hidden>true</Hidden>` ⇒
  动作改为 `powershell -WindowStyle Hidden -File start-hidden.ps1`，脚本内 `Start-Process -WindowStyle Hidden ... -Wait`
  拉起 node（`-Wait` 不可省，否则 node 被作业对象回收）。
- **判定层** `packages/vm-capabilities/psmod/gui.ps1` `Get-SessionHealth()` 五重判据：
  `sessionId>=1` + `OpenWindowStationW('WinSta0')` 能拿到句柄（比读 UI_NAME 字符串可靠，见 09-14 修复）+
  `explorer` 存活 + `LogonUI` 未起（未锁屏）+ 非黑屏 ⇒ `healthy`；`sessionId=0` ⇒ `unavailable`，锁屏/无 explorer ⇒ `degraded`。
- **历史坑**（`.workbuddy/handover/06-lessons-learned.md` A5/A6/A7）：锁屏时重启仍 degraded（判据刻意不放宽）；
  重启必须先 `/end` 再 `/run`；A7 记「经 SSH 触发时窗口站为 W 即便 SessionId=1」。
- **本次实测（17:27）**：`Get-ScheduledTask WinVMBridge.Service` → `Principal.LogonType=Interactive`、`UserId=User`、
  双触发器、`LastRunTime=17:01:37`、`LastResult=267009(0x41301 运行中)`，node pid 7892 **SessionId=1**
  且 health 报 `WinSta0/Default/interactive:true/healthy` ⇒ **从 SSH 跑 `schtasks /run` 这次确实落到了 Session 1**
  （前提：存在活跃未锁屏的交互登录会话）。A7 的异常落点在"无活跃交互会话/锁屏"时复现。
- **对 agent-desktop 的可复用结论**：同理用 InteractiveToken 计划任务（或 schtasks `/it`）拉起即可进 Session 1；
  SSH 直启必落 Session 0。**不是 agent-desktop 的缺陷，是进程父会话的问题**。

## §12 落地：agent-browser / agent-desktop 包进本项目（/mcp/browser、/mcp/desktop）18:55
- **形态**：vm-service 反向代理两个 stdio 上游 → 宿主 4 个 connector 共用**同一条隧道**、仅以路径区分。
  `connector:winvm`→`/mcp`(54) · `:winvm-a2a`→stdio 桥 · `:winvm-browser`→`/mcp/browser`(33) · `:winvm-desktop`→`/mcp/desktop`(10/75)。
- **决定性理由**：vm-service 跑在 Session 1 ⇒ 它 spawn 的上游**继承交互会话** ⇒ agent-desktop 能读真实桌面；
  SSH 直启只能落 Session 0（`apps:[]`）。这是「由 vm-service 代理」而非「VM 内另起桥」的根据。
- **零新协议代码**：`@winvm/core` 的 `StdioJsonRpcChannel`（现成、传输无关 `JsonRpcChannel`）+
  `@winvm/mcp-framework` 的 `McpClient`/`McpServer`。新文件只做生命周期：
  `packages/vm-service/src/mcp-upstream.ts`（懒启动/白名单/崩溃重建/退出清理）。
- **安全默认**：`/mcp/browser`、`/mcp/desktop` 不在 `http-guard` 硬编码豁免表 ⇒ 自动 fail-closed，**守卫零改动**。
- **模型扩展（纯附加）**：`ConnectorDecl.mcpPath?`（默认 `/mcp`）+ `NeutralPlugin.extraConnectors?`；
  adapter 渲染消费 `mcpPath`；卸载改按 `connector:<id>` / `connector:<id>-*` 精确清理（用 `-` 分隔防误删第三方）。
- **部署链**：`install-vm.mjs` 新增 `[4b/6] npm i -g agent-browser agent-desktop`（**失败不阻断**，`--skip-upstreams` 可跳）；
  `install-host.mjs` 写 extraConnectors（账户级 `connector:*` + 全局 `winvm-*` 都写）。
- **真机验证（全绿）**：
  - POC（`schtasks /it` Session 1 独立探针）：`desktop_snapshot app=chrome` → 117 节点/76 refs；
    `desktop_list_apps` → 3 应用；`agent_browser_open example.com` → Example Domain。
  - VM 内路由：`/health.upstreams` 初始 `idle`→后置 `browser ready 33/33`、`desktop ready 75/10`；
    `tools/list`=10；`desktop_list_apps`=3 真实应用；白名单外 → `未知工具：desktop_clipboard_get`。
  - **宿主经隧道端到端**：initialize / tools-list(10) / `desktop_list_apps`(3 apps) / browser(33) 全通过。
  - 单测：新增 `tests/unit/mcp-upstream-connectors.test.js` **13/13**；回归 host-adapter 37 / phase3-b2 6 / install-vm-task 8 / r3-uninstall 47 全绿；`tsc -b` 干净。
- **踩坑（重要）**：`--only 4` 重部署推的是**上次取包产物**（`~/winvm-deploy/overall-root/overall`，dist 为 11-16），
  不是源仓新 dist ⇒ 首轮验证 404。手工 `ssh2-conn put` 两个 dist 文件 + `schtasks /end→/run` 后通过（健康检查 11s 就绪，pid 3256 Session 1）。
  **规范部署必须先在母项目 `pack-release` 出新包**，否则「改了代码但 VM 还是旧的」。
- **另一坑**：PowerShell 5.1 `Set-Content -Encoding UTF8` 写 BOM ⇒ node `JSON.parse` 报
  `Unexpected token '\uFEFF'`。写 JSON 用 `[IO.File]::WriteAllText(..., UTF8Encoding($false))`，读时也 strip BOM。
