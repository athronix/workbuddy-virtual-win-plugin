### 四点十三、`~/.workbuddy/git-ssh.sh` 的 gitee 密钥分流错误（重要修复）

**现象**：`git push gitee main` 报 `[session-xxx] Auth error: Access denied`，看着像仓库权限问题。
**实测取证**（`ssh -T git@gitee.com`）：
```
id_ed25519        → Hi athronix(@athronix)          ← 原分流用的就是这把
id_ed25519_gitee  → Hi sanway-tech(@sanway-tech)    ← sanway-tech 的仓必须这把
```
**根因**：`git-ssh.sh` 的 `case` 只分了 `github.com` 与「其余」，gitee 落进了「其余」= `id_ed25519`（athronix 身份）。
**修复**：加 `*gitee.com*) key="$HOME/.ssh/id_ed25519_gitee"`。备份在 `~/wbtmp/git-ssh.sh.bak-20261123-155948`。

**GitHub 侧同类问题（不是分流能解的）**：
```
id_ed25519_github                 → Hi athronix（SSH 无 sanway-tech 权限）
gh hosts.yml oauth_token          → athronix, push=False
credentials.env GITHUB_PAT        → athronix, push=False
credentials.env GITHUB_PAT_SANWAY-TECH → sanway-tech, push=True  ← 只有这把能推
```
**结论**：推 sanway-tech 的 GitHub 仓必须用 `GITHUB_PAT_SANWAY-TECH` 走 HTTPS + 临时凭据文件：
```bash
# 凭据写 ~/wbtmp/.gitcred-sanway（0600），helper 指向它；token 不落日志不回显
GIT_CONFIG_GLOBAL=~/wbtmp/.gitcfg-sanway git -c core.sshCommand= \
  push "https://github.com/sanway-tech/<repo>.git" main refs/tags/v<ver>
```
`-c core.sshCommand=` **必须显式清空**（本仓 local config 指了 git-ssh.sh，URL 换成 https 也会被导向 SSH）。
GitHub 网络极不稳：本次 `github.com:443` 连续 2 次 `Could not connect`（65s 超时）后第 3 次成功，
**必须写重试循环并以 `ls-remote` 与本地 HEAD 比对确认，不能只看单次 push 的 rc**。

**Gitee attach_files 的鉴权坑**：`?access_token=` 查询参数会报
`{"message":"登录失效，无权限访问该资源","code":40001}`，**必须改成表单字段** `-F access_token=<tok>`。
（同一次发版里 create release 用查询参数是好的，只有 attach_files 不吃——极易误判成 token 失效。）
