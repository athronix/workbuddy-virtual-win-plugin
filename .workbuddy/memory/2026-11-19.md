### 本轮新暴露并修完的三个问题（P9~P11，v2.5.1）

**P9（P0）`-File` 执行 oneclick 必挂 —— 编码契约双向**
源文件必须 UTF-8 **无 BOM**（`irm|iex`/`Create` 把 BOM 当首字符 ⇒ param 块脱离参数区）；但 `powershell -File` 在 PS 5.1 **不认 UTF-8 声明**，按系统 ANSI(CP936) 解码无 BOM 文件 ⇒ 中文注释变乱码 ⇒ `?` 打断引号 ⇒ `ParserError`，**一行未执行**。修：源无 BOM + 落盘副本统一转 UTF-8 with BOM（四条路径全覆盖）。

**P10 第三个 node 运行时 store**
跑过 nvm-windows 的机器有**三个** store：`C:\nodejs`、`%LOCALAPPDATA%\Author Software\nvm`、**`%LOCALAPPDATA%\nodejs`（zip 装的用户级副本，漏了）**。判据加 `LOCAL_NODEJS_DIR`。

**P11 僵尸 node.exe 镜像永不可删**
pid 6048 = `codebuddy mcp remove agent-desktop`（部署脚本自己拉起、未回收）。它是**僵尸**：`HasExited=True` 但父 `cmd.exe`(session 0) 不关句柄 ⇒ `Terminate` rc=2、`taskkill`「没有运行实例」；父进程同样杀不掉。对策：第三轮 `EvictLocked` 把死镜像**改名移出**到 `C:\ProgramData\WinVMStale` + 登记 `PendingFileRenameOperations`（开机删），目录即可回收 ⇒ 不重启 VM 也能 PASS。

### 三条通用教训（写进门禁注释）
1. 「源文件编码」与「执行副本编码」是两个独立契约，按**执行路径**分别满足。
2. 「清完还残留」先怀疑**清单不全**，再怀疑删不掉。
3. Windows「访问被拒绝」有四种成因（ACL/句柄/僵尸/只读），**先用 Restart Manager 拿持有者名单再动手**；`rmdir /s /q` 会把它变成无信息的静默失败。Restart Manager 是唯一 in-box 的「谁占着这个文件」查询手段。

### 新缺陷
**P12 4a 假绿（P0）**：判据只看 rc，但 `prepare-vm` 的 ps1 在 DB-3/DB-7 失败时只 `Write-Output "[MANUAL] ..."` 不 `exit 1` ⇒ rc=0 ⇒ `[OK] 依赖就绪`。故障推迟到 4b 才以 `VM_START_FAILED` 现身。**只有「彻底卸载→从零」才会暴露**（测试机都已有 node）。
修：`_deps_gap()` 扫文本 → 有界重试一次 → 兜底装 node → `st_end 1 FAIL`。
教训：**判据要锚定「结果」，不能锚定「退出码」**（被调方承诺「部分失败不阻断」时，rc 天然承载不了整体是否达标）。

**P13 node 兜底**：
- ① 镜像瞬时抖动无重试（DNS 六域名全 OK、443 三处 True、代理关闭；手工同 URL `bytes=37618919` 一次成功）⇒ DB-3 一次失败即放弃。

- ③ **实测否证「删不了但能覆盖」**：整树 `Copy-Item -Recurse` 遇映射中的 node.exe 同样 `IOException` 并中断整个脚本。
- 真机 Restart Manager 定位占用者：`PID=12904` 命令行 `"…\nodejs\node.exe" "C:\WinVMBridge\packages\vm-service\dist\cli.js"` —— **WinVM 服务自己在用**（不是 bug，是常态）。另 `PID=10480 XtaCache`。
