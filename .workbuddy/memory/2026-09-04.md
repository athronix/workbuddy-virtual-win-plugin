## 第十一轮：隐藏 VM 控制台窗口（Q3/Q4a）+ 补 buildTaskXml 单测
- 用户反馈 4 问：① 要「部署好后的 `winvm-plugin` 命令」非 `.mjs`；② uninstall 后宿主未见删除物、VM 侧能否进系统回收站；③ VM 残留 `node.exe` 日志窗口应隐藏；④ 管理员 PowerShell 重启服务后又弹窗口（4a）且 GUI 仍 `degraded`（4b）。
- **Q3/Q4a 根因（重要认知修正）**：任务 XML 用 `<LogonType>InteractiveToken</LogonType>`（GUI 能力域硬性要求：Session>=1 才能截图/SendInput），而 **Windows 对 InteractiveToken 任务忽略 `<Hidden>true</Hidden>`**。原 `<Actions>` 直接以 `node.exe` 为动作进程 → 必弹常驻控制台窗口。`schtasks /run` 重启走同一份任务定义，故 4a 与 Q3 同源。
- **修复**：`buildTaskXml` 额外生成 `delivery/.generated/start-hidden.ps1`；任务动作改为 `powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "<ps1>"`，脚本内 `Start-Process -WindowStyle Hidden -FilePath $nodeExe -ArgumentList $cliArgs -WorkingDirectory $workDir -Wait` 拉起 node。
  - 用 `-File` 而非 `-Command`：node 参数含带双引号的路径，`-Command` 需再嵌一层命令行引号（`/"` 转义）极易出错；`-File` 只剩一层，参数原样写进 `.ps1`。
  - `-Wait` 让任务在服务存活期间保持 Running，保留 `schtasks /end` 可终止、崩溃触发 RestartOnFailure 的原语义（若用 `Start-Process` 不带 `-Wait`，任务动作会立即结束、进程可能被作业对象连带回收）。
  - 保留 `InteractiveToken` + `<Hidden>true</Hidden>`（前者是 GUI 前提，后者对非交互回退仍有意义），隐藏改在**进程创建层**做。
- **Q4b 结论（未改码）**：`gui.ps1 Get-SessionHealth` 判定 `interactive = SessionId>=1 && WinSta0 && explorerAlive`，且 `locked`（LogonUI 存在＝锁屏）→ `degraded`。重启那一刻 VM 处于**锁屏**或 **Explorer 未运行**，故降级。"交互式会话启动即可用 GUI"没错，但**前置条件未满足**。判定刻意保留、未放宽；解法是先解锁/登录桌面、确认 Explorer 在跑再重启。
- **Q1 结论**：`winvm-plugin` 三件套已由 `deployWinvmPlugin` 部署到宿主插件缓存根 `C:\Users\towyq\.workbuddy\plugins\cache\winvm\winvm-bridge\0.1.0\`（`.mjs` + `.cmd` + 无扩展名 bash 启动器），仓库 `delivery/` 也有一套；实测两处 `./winvm-plugin check` 均可用（输出「宿主机部署完整 ✅」）。默认**不在 PATH**，需 cd 进该目录或把目录加进 PATH。
- **Q2 结论**：宿主删除物进**系统回收站**；VM 侧默认落 `<repoRoot>/.uninstall-trash/<时间戳>/`，**不会**进 Windows 回收站 —— 唯有在 VM 内 **RDP 交互会话**运行 `install-vm.mjs --uninstall --yes --recycle-bin` 才走系统回收站（SSH 下不可见）。
- **可测试性改造**：`buildTaskXml` 新增可选 `outDir` 参数（不传时行为不变，仍写模块级 `taskXmlPath`）；模块末 `main()` 加入口守卫 `resolve(process.argv[1]) === __filename`，使其可被 import 而不触发真实部署。**改动前已核对**：`install-vm.mjs` 在全仓仅以子进程/ssh 调用（`winvm-plugin.mjs`、`setup.mjs`），从无 import，故守卫不改变既有行为。
- **新增单测** `tests/unit/install-vm-task.test.js`（8 项）：任务动作不得直接是 node.exe / `-File`+`-WindowStyle Hidden` / ps1 内 `Start-Process … -Wait` / `cliArgs` 原样落地（含内层双引号）/ 单引号按 PS 规则双写转义 / UTF-16LE+BOM / 保留 `InteractiveToken`。
- **文档更正**：`DEPLOYMENT.md` 两处「`Hidden=true` 不弹 node 窗口」为错误说法，已改为真实机制；并补充「交互式会话 ≠ GUI 一定可用（锁屏/Explorer 未跑 → degraded）」。
- **验证**：`node --check` 通过；全量单测**逐文件** **195/195 全绿**（基线 187 + 新增 8）；实跑打印生成物核对引号无误。
- **教训固化**：① 计划任务「隐藏窗口」不能在 XML 层做，必须在进程创建层（InteractiveToken 会忽略 Hidden）；② 交付脚本类模块想加单测，需先确认「是否会被 import」再加入口守卫，并核对全仓调用方式。
