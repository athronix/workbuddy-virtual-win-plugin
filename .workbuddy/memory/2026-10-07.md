## ⚠️ 可复用教训（团队纪律 · 已修正版）
1. **「工具不存在」的判定必须穷尽路径**：`command -v git` 为空 **不等于** 没有 git。本环境 git 在 **`/storage/Users/currentUser/.harmonybrew/opt/git/bin/git`**（harmonybrew，不在 PATH）。我曾据此把worker 的真实 commit 证据误判为「臆造」并打回——**判定前须搜 `.harmonybrew` / `~/.*brew` 等前缀，不能只搜 PATH 与 `/data/storage/el1/bundle`**。同理 `tsc` 也在 `node_modules/.bin/`。
2. **但仍要坚持独立核验**：worker 确实存在「复述主理人骨架里的旧坐标并声称已核实」的倾向（本次门 0 行号 `:227` 就是原样回传我给的旧数，实际 `:230`）。所以**骨架里给的坐标必须先自己实测**，且 worker 交付后仍须主理人用 Read/grep/wc 复核——只是**结论要基于实测，而非基于「他没这工具所以不可能」的推理**。
3. **打回时区分「不可核实」与「虚假」**：可用「未核实/待核实」降级，不要直接断言臆造。
4. **`cfd4a8d` 顺带解答了一个此前悬空的问题**：`providerApprovalTruth` 之所以在 `/health` **顶层**，是因为 `providerHealth` 顶层字段在最后一跳被丢弃，故改为纯附加透传——T05 报告未写原因，由该 commit 补全。
