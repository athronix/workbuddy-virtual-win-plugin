## 第十四轮补：VM check 「服务端口监听中 ❌」诊断
- 用户 VM 内 `winvm-plugin check` 显示 4/5 ✅，仅 `127.0.0.1:18443` 未监听。
- 根因：`check` 只验证计划任务**注册**，不启动服务；VM 侧任务用 `LogonTrigger`（仅下次登录触发）。用户是**已登录状态下经宿主 SSH 跑 install-vm.mjs**部署的，触发器未触发 → 服务从未启动 → 端口自然没监听。属预期，非部署失败。
- 修复（VM 交互式窗口执行）：`winvm-plugin server start`（= `schtasks /run /tn WinVMBridge.Service`），再 `winvm-plugin check` 确认端口 ✅。需 GUI 则 start 后 `winvm-plugin health` 核验 `windowStation=WinSta0/interactive=true`，degraded 则按 Q3 在 RDP+普通用户 PowerShell 下 `server restart`。
- 代码：winvm-plugin.mjs 的 VM check 结论分支改为明确打印上述修复命令（不再含糊）。提交 `928b113`。

## PATH 写入后广播 WM_SETTINGCHANGE（免注销生效）
- 用户反馈：VM 内 SSH 能跑 `winvm-plugin health`，但 RDP 桌面里 PowerShell/cmd 报「命令找不到」。根因=RDP 会话在 PATH 变更前已登录，env 登录时一次性载入后不自动刷新（陈旧会话）；SSH 每次新建登录会话故读到新 PATH。修复=彻底注销并重连 RDP（同时触发 LogonTrigger 拉起服务、解 degraded）。
- 增强（用户要求）：`path-util.mjs` 的 `setUserPathRaw()` 写完后调用新增内部函数 `broadcastEnvChange()`，向 `HWND_BROADCAST` 发 `WM_SETTINGCHANGE`(0x1A, lParam="Environment")，让已运行 explorer 重新加载环境 → 部署后 RDP 里**新开**终端免注销即可拿新 PATH（旧窗口仍须重开）。best-effort：仅 win32、忽略返回、SMTO_ABORTIFHUNG+5s 超时，SSH 无桌面也不影响主干。
- 验证：`node --check` 通过；PowerShell here-string 定界符 `@'` 开/`'@` 闭（行首）已核对；path-util 单测 9/9 通过。**已提交 `aa7ea0d`**（2026-09-09）。
