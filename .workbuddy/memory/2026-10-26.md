### ACP 原生通道实证（为 `workbuddy-native` 新 provider 立项取证）

用户设想：VM 端 workbuddy 提供 ACP，A2A 只包装它。**实测结论：设想成立，但"服务端"是 codebuddy CLI 而非 WorkBuddy.exe。**

- **当前实现（provider=`workbuddy`）不走 ACP**：`@winvm/adapter-agent-workbuddy-llm` 用 `-p --input-format stream-json --output-format stream-json --session-id` 拉起 CLI 子进程（`PERSISTENT_CLI_ARG_TEMPLATE`，persistent-session.ts:112），并注入 `--mcp-config {mcpServers:{winvm:{type:'streamableHttp',url:'http://127.0.0.1:18443/mcp?dtid='}}}` 让 CLI **反向回连**本服务 54 能力。全仓 grep `agent-client-protocol`/`AgentSideConnection` **零命中**（CL-018 曾评估 `--acp` 但选型 stream-json）。
- **`/a2a` 与 `/mcp` 同进程**：`packages/vm-service/src/server.ts:2168` 同一 HTTP server 内路由分发 → 不存在独立部署的 "a2a service"，A2A 是 vm-service 的一条路由。provider 由 `loadProvider(cfg.agent, bridgeCtx)`（core/src/bridge/loader.ts:73）按 `agent.providers[id].package` 动态加载。
- **VM 上无 `workbuddy` 命令**（实测 `Get-Command workbuddy` = not found）。`codebuddy` = nvm shim → `...\v24.21.0\node_modules\@tencent-ai\codebuddy-code\bin\codebuddy`，v2.167.0。
- **WorkBuddy 桌面版 = ACP client，不是 server**：`C:\Program Files\WorkBuddy\`（Electron 204MB）内置 `@genie/agent-harness` v0.2.0-beta.15 + `@agentclientprotocol/sdk`（`lib/server/rpc-module.js` 导入其 `methods`）；其 bin `agent-harness.js` 直接跑报 `AgentHarnessBinaryResolutionError`（缺 `@tencent-ai/agent-harness-win32-x64` native）→ **不能作为独立 ACP server 被 spawn**。
- **ACP 真实可用形态 = `codebuddy --serve --acp`（HTTP，非 stdio）**：
  - `--acp` 纯 stdio（ndJsonStream）在本机静默退出（exit 0、stdout/stderr 全空，7s）→ 不可用；
  - `--acp --acp-transport streamable-http` 同样静默退出（无监听）→ 不可用；
  - **`--serve --acp --port <p> --host 127.0.0.1` 成功起服务**（打印 Endpoint + Web UI + `--auth password` 默认随机密码；`--auth none` 可关；起服务走 Spring 风格路由，**所有非白名单路径必须带 `x-codebuddy-request` 头，否则 403**）。
- **ACP over HTTP 全链路 POC（已跑通，端口 18453）**：
  1. `POST /api/v1/acp/connect`（带 `x-codebuddy-request`）→ 200 `{connectionId, sessionToken}`（**connectionId 由服务端签发，自造 id 会 409**）；
  2. `POST /api/v1/acp` + header `acp-connection-id: <server-issued>` + body JSON-RPC `initialize` → 200 `text/event-stream`，`data: {"result":{"protocolVersion":1,"agentCapabilities":{promptCapabilities:{image,embeddedContext},mcpCapabilities:{http,sse},loadSession:true,delegateToolsSupport:true,multitaskSupport:true,metaPromptSupport:true},"authMethods":[iOA,external,internal,selfhosted]}}`；
  3. 同连接 `session/new` → 200 SSE 先推 `session/update`（`config_option_update`：permission mode 选项 default/acceptEdits/plan/auto）再返 sessionId。
  - 注：加 `authorization: Bearer <sessionToken>` 会命中 `Server already initialized`（-32600）→ 该 token 不用于 JSON-RPC 认证头。
- **路由常量来源**：`dist-server/codebuddy.js`（8.6MB）内 `isPassiveSubscription` 正则 `^\/api\/v1\/acp(?:\?|$)`；`/acp/bootstrap` 是客户端把 `/acp` 替换得到的 bootstrap 路径（服务端 404，仅 client 侧拼接）。
- **结论**：`workbuddy-native` = 新增 provider，**ACP over HTTP 包装**（`--serve --acp` → `/api/v1/acp/connect` → `initialize`/`session/new`/`session/prompt`，`session/update` 流式映射 A2A 进度、`session/request_permission` 映射现有审批双闸）；不改现有 `workbuddy`（stream-json）实现。
