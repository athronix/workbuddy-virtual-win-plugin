### 架构定调（用户拍板）
- **1+4 双通道**：统一能力模型 + 可替换桥接 SPI；4 领域 Skill + 1 总控；MCP（工具级）+ A2A v1.0（任务级）双协议同端口 18443。
- 三层解耦：宿主插件规范（host-sdk 中性化）→ WorkBuddy 适配器；VM 内 Agent 桥接 SPI → adapter-agent-workbuddy（可替换）。

### 关键技术坑（已解决，复用价值高）
1. **ESM 无 `__dirname`**：ps-bridge 用 `import.meta.url` 派生路径，否则回退到 `process.cwd()` 找不到 psmod。
2. **PowerShell 5.1 兼容**：剔除 `??`/`?.` 等 PS7 语法；能力模块须在脚本作用域**预加载**，函数内 dot-source 返回即失效。
3. **maxRisk 语义**：仅当 A2A 委派请求显式声明 `maxRisk` 时才做范围封顶；MCP 直调由审批闸管辖，否则 L2/L3 永远无法执行。
4. **路径策略边界**：仅命令类参数（command/cmd/script…）做 token 抽取；普通路径参数整体匹配；避免"命令串误判为路径"被误杀。
5. **宿主 mcp.json 零覆盖**：以 JSON patch 增量写入指针 `/mcpServers/connector:winvm`，绝不整体覆盖用户已有连接器（安全红线）。
6. **安全基线**：VM 服务强制 `requireLoopbackBind`；策略 mergePolicy(DEFAULT_POLICY, cfg.policy) 空 {} 即保留强默认。
