### 结论与纪律

**无法复现当时的假成功，但必须按「发生过」来防。** 现在的验证纪律升级为：

> **凡「已推送」断言，必须用与 push 无关的第二通道读取远端 SHA。**
> 可接受：`Gitee API /repos/{o}/{r}/branches/main`、`GitHub API /commits/main`、
> 对端独立 `ls-remote`。
> **不可接受**：只看 `git push` 的 `a..b main -> main` 输出；
> 也不可只看自己 `git branch -vv` 的跟踪引用（那是本地缓存）。

补充可靠信号：`git branch -vv` 里的 **`ahead N`** —— 有 ahead 就是没推上去，
这是本地就能看出来的、不依赖网络的硬信号。
