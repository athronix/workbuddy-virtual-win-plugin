## 4. 接线改造（融合真正生效的关键）

三个脚本原先硬编码 `HOS="$HOME/.workbuddy/skills/hos-winvm-ssh-tunnel"`，现统一改为：

```bash
# v1.6.0: the tunnel lifecycle is INTERNAL (hos-winvm-ssh-tunnel v2.3.0
# merged into this skill). HOS_TUNNEL_SKILL stays a backward-compatible
# override pointing at a standalone skill root; default = THIS skill root,
# so every "$HOS/scripts/..." resolves to our own scripts/ directory.
HOS="${HOS_TUNNEL_SKILL:-$(dirname "$_here")}"
```

- 影响文件：`scripts/channel.sh`、`scripts/undeploy.sh`、`scripts/build-vm-bundle.sh`；
- `$(dirname "$_here")` 是纯字符串操作（规避鸿蒙 `cd`/getcwd 相位异常），解析为本技能根，故 `$HOS/scripts/host-generate-key.sh`、`verify-tunnel.sh`、`host-rollback.sh`、`winvm-setup-sshd-and-key.ps1` 全部落到自带 `scripts/`；
- 保留 `HOS_TUNNEL_SKILL` 覆盖能力 → 已装独立 skill 的旧环境仍可显式走原路径；
- 错误提示同步去「安装 hos skill」字样：`NO_HOS_SKILL` → `NO_TUNNEL_SCRIPTS`、`NO_HOS_TEMPLATE` → `NO_ROLLBACK_TEMPLATE`；`deploy.sh` C1 的处置提示改为「检查内置通道脚本是否在场」；`build-vm-bundle.sh` 的 `PASTE-THIS.txt` 描述改为内置模板。

按规范先跑 `check_environment.py --json` → `status=partial`（git / git.identity / gh / gh.auth / python OK；`gh.scope.workflow`、`GITHUB_READ_TOKEN`、`GITEE_TOKEN` 元数据缺）。继续执行可行的降级路径：

**鸿蒙侧必要适配**（skill-dev-git 源于 Windows）：
1. `python3` / `git` / `gh` 全部绝对路径（`/data/service/hnp/bin/python3`、`~/.harmonybrew/opt/git/bin/git`、`~/.harmonybrew/opt/gh/bin/gh`），脚本内 `run()` 注入 PATH；
2. token 链 `env > gh hosts.yml(workflow scope) > .env > credentials.env`；gh 缺位时 REST API 降级；
3. python urllib 用系统 CA bundle（`/etc/ssl/certs/cacert.pem`）规避 `CERTIFICATE_VERIFY_FAILED`；
4. per-repo `core.sshCommand=~/.workbuddy/git-ssh.sh` host-aware 密钥分流，**不用 `~/.ssh/config`**（hmdfs 属主 file_manager 会被 ssh 拒用）；
5. `dist/` 不入库、`/tmp` 只读一律改用 `$HOME/wbtmp`、shell 启动 getcwd 异常全程用绝对路径。

## 9. 误报风险与待办（必须声明）

1. **本轮未跑真机 E2E**。合并后的三条运行时路径（通道不在 → `channel.sh ensure` 调内置 `host-generate-key.sh`；通道在 → VM SYSTEM post 回滚；通道坏 → VM 合并包）只有静态 + 本地动态证据，`host-generate-key.sh` 因会写 `~/.ssh` 与运行期基线而**刻意未实跑**，以免污染现网密钥。建议第三轮 E2E 加一条「故意断通道后 undeploy」用例。
2. **母项目 V1.4.27 pack 仍未执行**。本次发布的是 skill 仓自身 zip；随母项目 tag 分发的 `winvm-plugin-deploy-skill.zip` 需再 pack 一次。届时建议把 6 个内置通道脚本**显式钉进 pack V11 的 `need` 列表**（当前靠 `copySkillEntry` 目录白名单自动入包，已模拟验证但无断言钉死）。
3. **pack V11 断言名仍写「通道外委章」**，其断言面是字符串包含（`SSH 免密通道生命周期` + `hos-winvm-ssh-tunnel` + `INSTALL_PROMPT.md`），合并后仍全绿；语义已变，建议后续 V12 把断言文案改为「内置」。
4. `check_environment` 的 `partial` 项中 `gh.scope.workflow` 元数据缺 workflow，但 dispatch 实证成功、sync success、marketplace 版本追平、双端 HEAD 一致 —— **以实证为准**；`GITEE_TOKEN` 未设时镜像步骤由聚合仓 CI 侧凭据完成，本次 `re_pulled=false` 表示 HEAD 本已追平。
5. 原独立 skill 仍可单独使用，与本技能共用运行期状态目录；若将来独立升级到 v2.4+，本技能内副本**不会自动同步**，需按本次映射表手工再并一次（已在并入文档的溯源块写明版本）。
