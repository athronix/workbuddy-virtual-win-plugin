## 五、阻塞与解除：通道 WEDGE（已闭环）

`4a prepare-vm` 报 `ssh2 连接错误: Timed out while waiting for handshake`，随后 `--only 4` 在通道门禁处止损。

同一时点的通道三个面：

| 面 | 结果 | 说明 |
|---|---|---|
| `ping 172.16.100.2` | 通，0~2ms，0% 丢 | 网络层无罪 |
| `curl :18443/health` | **200** | 隧道**长连**活着，数据面通 |
| `ssh2-conn.mjs ping`（新建连接） | 连续 6 次超时 | 新建握手死 |

### 5.1 三段取证（把「等」还是「修」变成了可判定的问题）

| 探针 | 实测 | 结论 |
|---|---|---|
| 裸 TCP 连 :22 读 banner（`net.connect`，非 ssh 库） | **连接 7ms，12s 零字节** | 内核完成握手、sshd 未发 banner ⇒ 卡在 accept/预认证段 |
| 静默 180s（零新连接）后单次探测 | 仍 12s 超时 | **证伪**「探测风暴抽干 accept 槽（MaxStartups）」 |
| VM 内进程清单（经隧道 MCP `system.process.list`） | `sshd-session` 仅 2 个（隧道 `-R` + 一个 `-z`） | 排除会话堆积 |
| VM 内自检 ssh（pid 9128，oneclick 脚本遗留，`ConnectTimeout=5`） | 卡住不退，且它是连 **127.0.0.1** | 连回环新建都挂 ⇒ guest sshd 自身停摆，非宿主 NAT/proxy |
| `system.eventlog.query`（System 日志 120 条） | 0 条 ssh 相关 | 静默停摆，服务未崩（`sshd=Running/Auto`） |

结论：**guest OpenSSH 的 accept/预认证段停摆，长连不受影响**（所以 `health=200` 与「新建全死」能长期共存 —— **health 不是通道判据**）。

### 5.2 解除（经隧道重启 sshd，不重启 VM）

隧道长连可用时就地修：`system.service.control{name:"sshd",action:"restart"}`（L1，966ms，`status=Running`）。
重启只杀「新建连接的接受能力」，已建立的长连存活 ⇒ 隧道不断、`health` 持续 200；修完立刻 `ssh2-conn.mjs ping` → **`pong ready`**。

⚠ 期间踩到一个**假红**：手测 `ssh2-conn.mjs ping` 忘了带 `WINVM_VM_KEY`，ssh2 回落默认 `~/.ssh/id_ed25519` → 报 `All configured authentication methods failed`，酷似「认证被拒」。同秒 `ssh -i <真钥>` 认证成功即证伪。**判据：`Timed out while waiting for handshake`=WEDGE；`All configured authentication methods failed`=钥配错**。

### 5.4 复验当场抓到的三个真缺陷（都已修 + 入自检）

| 缺陷 | 现象 | 根因 | 修法 |
|---|---|---|---|
| **4c 假绿** | 首跑 `health_http=ERR` 仍判 PASS | `vmcheck.ps1` 是**纯报告器**（无退出码），4c 只看 `ps-run.sh` 的 rc ⇒ 「脚本跑完=PASS」，判据不达标照绿 | 4c 自解析 JSON 逐项断言（task_state/listen_count/side_json/bridge_dir）+ health 双口径（VM 自检 5s 窗被自身载荷挤占时，以宿主侧 200 为准）；新增自检 `vmcheck-assert` + 变异 M7 |
| **复用假 FAIL** | 二次 verify 报 `REUSED PROBES 0/0` 1s FAIL | stamp 只记 pkg+epoch，复用却去读**本轮新建的空目录** → 三探针全 meter-missing | stamp 增记 `logd=`，复用必须读那个目录；缺失则回落冷跑；并入 `probe-count` 断言 |
| **5d 乱码** | `VM: task=��������` | PS5.1 重定向 stdout 用控制台代码页（zh-CN=GBK），宿主按 UTF-8 读 | 5d 载荷首句 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`，保持纯 ASCII 载荷 |

## 六、为并行做的加固（真机实证驱动）

| 加固 | 起因 |
|---|---|
| `deploy-3` 3b：health 已 200 就**跳过 restart** | restart 会重建到 VM 的 ssh 连接，与并行的第 4 步抢握手槽，实测把 4a 打成 `Connection lost before handshake` |
| `deploy-4` 4.0：通道门禁最多等 60s（不重启 VM） | 瞬态窗能自愈；超时才止损，且提示"只重跑第 4 步" |
| `deploy-4` 4a：建连类失败**一次有界重试**（间隔 15s） | prepare-vm 幂等只读，重试安全 |
